# 3 分钟演示脚本

> 目标：让对方在 3 分钟内看到「结构化 — 可比较 — 有出处」这三件事，而不是看完所有功能。

## 准备（演示前 5 分钟）

- 后端 8081、Agent 8001、前端 3000 全部启动
- 用 demo / demo1234 登录（8 条记录，2025-08 ~ 2026-10，异常项 6→5→3→1）
- 打开两个标签页：**趋势页** 和 **最近一次记录详情**
- 备一张化验单照片

---

## 0:00 — 0:20 开场

> “我家里人要定期复查，每次拿到化验单都只能看箭头，换个医院区间就变了，一年下来根本说不清是好转还是变差。”
>
> “这个项目做一件事：**把化验单变成可比较、可追踪、有出处的数据**。”

**不要说**“我做了一个 CRUD 系统”或“我接了个大模型”。

## 0:20 — 1:00 抽取与校对

1. 打开上传页，传化验单 → 显示抽取结果
2. 强调：**别名归一**（血糖 → 空腹血糖）、**单位换算**（mg/dL → mmol/L）
3. 点进校对页，指出三种状态：已匹配 / 待确认 / 未匹配

> “识别的难点不是读字，是**把不同医院的不同写法归到同一个指标上**。196 行 × 8 张单据的评测里，数值准确率 96.9%。”

## 1:00 — 1:40 趋势图（最能打的一屏）

1. 切到趋势页，选「空腹血糖」
2. 指参考带：**不同医院区间不同，所以参考带是分段的**
3. 指出异常点被标出来

> “很多系统用全局常量画一条线，但真实世界里每家医院区间不一样。我这里按**每次报告自己的区间**画，所以‘三个月前超标、现在正常’是能看出来的。”

## 1:40 — 2:30 Agent 三个问题（按顺序问）

**① 取数（证明不编数据）**

> 「我最近几次血糖是多少？」

期望：给出具体日期和数值，带医院。

**② 解释（证明分工）**

> 「为什么两家医院的参考区间不一样？」

期望：引用 WS/T 405-2012 第 5.3.2 条，说明人群与采血方式差异。

**③ 知识（证明有出处）**

> 「抽血前要空腹多久？」

期望：引用 WS/T 661-2020 第 4.1 条，8~14 小时，并说明「空腹期间可少量饮水」。

## 2:30 — 2:50 边界（这是加分项，不是减分项）

> 「这个结果严重吗？要不要吃药？」

期望：明确拒绝 → 说明能提供什么 → 给三个可点的问题。

> “模型不负责下判断。能力分四级，L2 医学判断由**代码强制封顶**，不是靠提示词自觉——提示词会被绕过，代码不会。”

## 2:50 — 3:00 收尾

> “这套东西的成本和风险都是可控的：11 个工具、6 轮上限、20 秒超时、三层降级，Redis 挂了也不影响主流程。”

---

## 可能被追问的三个问题

| 追问 | 怎么答 |
|---|---|
| “这不就是调 API 吗？” | “模型自己决定调哪个工具、调几次。A/B 实验里我把提示词里的路由规则删掉、只靠工具描述 + 代码强制首轮取数，token 省了 29%，命中率不变。” |
| “为什么不用向量库？” | “语料只有百级、中文术语精确匹配更强、结果要可复现。检索层 80 行、零依赖。语料过万再考虑。” |
| “准确率怎么测的？” | “196 行人工标注做基线，分指标召回、数值准确、单位识别三项；Agent 侧 35 题跑四项硬指标，都在 README 里。” |

## 不要做的事

- 现场改代码或跑测试
- 展示调试页（信息太密，容易跑题）
- 解释架构图超过 30 秒
- 主动说“还差什么”（被问再说）
